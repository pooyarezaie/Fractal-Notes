# Accessibility audit and scoped fixes

Target: https://fractalnotes.com and local changes based on main commit
`9ad9fb54c1fa5a46472c4cd4e4437268d6fdf602`. Standard: WCAG 2.2 levels A and AA.
This is a sampled audit and regression suite, not a WCAG conformance claim.

## Scope and method

The automated baseline loaded nine routes at 1280×900 and 320×900 CSS pixels:
home, the complex-numbers landing page, introduction, nth-roots,
julia-mandelbrot, the statistics graph note, the problem-solving completion
note, the owner's author page, and 404. Both the public site and the isolated
local baseline completed all 18 scans. axe-core 4.11.0 reported violations in
12 scans: `link-in-text-block`, plus `scrollable-region-focusable` on the three
complex-number notes at 320 pixels. Results with zero violations still contained
review-needed checks; they are not proof of conformance.

Source inspection covered the shared layout, CSS, both lab scripts, KaTeX
MathML, the staged-disclosure handler and the Pages workflow. The revised build
is also tested with Playwright 1.58.2 for keyboard activation, focus containment
and return, Escape, responsive breakpoints, numeric alternatives to dragging,
RTL slider keys, reduced motion, image loading and visible-content clipping.

The user's computer browser was requested, but the browser-control inventory
returned no available browsers and opening the in-app browser failed. No manual
keyboard walk-through or screen-reader session ran in that browser. Test
screenshots were generated by headless Chromium and visually inspected; those
are distinct from manual browser or assistive-technology testing.

The author grid can shrink below its previous fixed minimum. The four notes
loading changed lab scripts now use the existing build-stamp convention so the
service worker cannot serve an older unversioned script on the first return
visit. No author prose or mathematical explanation was removed or rewritten.

## Maintenance and execution

- `npm ci` installs the reconciled lockfile, including the previously declared
  `serve` dependency and the pinned axe test dependency.
- `npm run lint` performs JavaScript **syntax** validation. The repository had
  no ESLint or general test command before this change.
- `make build-prerender` builds Jekyll and prerenders all 44 whitelisted pages.
- `npm run test:a11y` runs the sampled axe scans and interaction checks.
- `A11Y_REPORT=/tmp/results.json` saves machine-readable evidence.
- `A11Y_SCREENSHOTS=/tmp/a11y-images` saves interaction screenshots.
- `.github/workflows/accessibility.yml` performs these checks on pull requests
  with read-only repository permissions and no deployment job. README,
  PROJECT_NOTES and AGENTS document the new commands consistently.

## Remaining limits

Actual browser-UI zoom, manual screen-reader output (including Persian MathML
and live announcements), touch/voice/switch input, forced colors, all diagrams'
alternative-text adequacy and every content page remain unverified. The resize
test doubles computed text sizes and uses 320 CSS pixels; it is an emulation,
not a claim that browser-UI zoom was manually tested. Mathematical displays and
tables may scroll locally as permitted for intrinsically two-dimensional
content. Native dialog/inert behavior has been tested only in Chromium here.
No production deployment, merge, or change to unrelated local work is included.

## Final local result

The complete final suite passed: 18/18 sampled scans had zero axe violations;
12/12 interaction groups passed. JavaScript syntax checks and `git diff --check`
passed, `npm ci --offline` succeeded, Jekyll built successfully and all 44
whitelisted pages prerendered. Four test screenshots (menu, image dialog,
roots controls and reduced-motion statistics graph) were visually inspected.
The committed `scripts/accessibility-results.json` records the final sampled
results, including axe's review-needed checks.

GitHub publication remains blocked: the HTTPS credential helper had no usable
GitHub login; the existing SSH agent refused to sign with the configured
security key. This establishes unavailable authentication, not an independently
confirmed repository-permission denial. No workaround authentication was used.
There is no remote branch, PR, remote-commit verification or CI result to claim.
The PR-only workflow is prepared and its checkout/setup-node release tags were
verified publicly, but the workflow has not run remotely. Restore normal GitHub
write authentication in this environment before pushing the local branch and
creating a **draft** PR against main. Do not merge or deploy.
